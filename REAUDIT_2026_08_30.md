## 5. Verified closed since this re-audit was written

The following gaps from the table above have been implemented and verified in code:

- **Public site:** trust bar, contextual CTAs, live "By the numbers" stats, risk-reversal microcopy, and unified design system.
- **Finance:** expenses enforce remaining budget allocation, refund credit notes reduce net revenue in reports, reports UI + CSV export exist.
- **Franchise:** org-unit admin UI covers create/edit/move/delete and unit-role assignment; provisional chapters are auto-promoted to chartered when readiness passes.
- **Franchise:** chapter officers self-manage via the officer portal; admin access escalation is blocked to full admins only.
- **Governance:** `castVote` validates active home-chapter membership; term limits are enforced at nomination time.
- **Onboarding:** manual milestone checklist UI exists in the member dashboard.
- **Engagement:** newsletter signups create real rows in `newsletter_subscribers` with admin list/export.
- **Operations:** scheduler uses an atomic conditional update to claim the daily pass, making it horizontal-safe.
- **Security/ops:** rightmost trusted-proxy IP, tRPC mutation rate limits, async scrypt, payment URLs from config, non-root Docker user, SIGTERM handling, `.dockerignore` secret exclusions, and a blocking CI audit gate with 0 high/critical production vulnerabilities.

### Design-system unification details

- All public marketing pages (`public/*.html`) now load the same `home.css` light-theme system; the previous trust fracture between the homepage and interior pages is gone.
- A new shared `public/tokens.css` file contains the single source of truth for the core palette, typography, and motion primitives.
- Both `public/home.css` and `public/styles.css` import `tokens.css` and reference its variables for exact-match values, ensuring the public site and member portal derive from the same design tokens.
